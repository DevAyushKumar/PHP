-> What are superglobals ?
- user-defined vs pre definedd: Unlike user-defined variablse you can create yourself (e.g. $name = "Ayush";), predefined varaibales are built directly into the PHP language.
- Global accessebilility: Superglobals can be accessed from anywhere in you code, regardless of variable scope (such as inside or outside function) 
- Syntax: Written with a dollar sign, an underscore, an all-caps name, and square brackets to specify a key/index 

-> Complete list of PHP superglobals
1. $_SERVER : Holds information about header, paths and script locations

2. $_GET : Collects data sent via URL parameters (visible in the browser address bar as an associative array)

3. $_POST : Collects form data submitted invisibly in the HTTP request body 

4. $_REQUEST : Combines data from $_GET, $_POST and $_COOKIE

5. $_Files : Stores metadata (size, name, file extension) about files uploaded via an HTML form

6. $_COOKIE : Accesses or sets small files embedded by the server onto the user's computer

7. $_SESSION : Stores Stores the information on the server side across pages until the browser/session is closed

8. $_ENV : Accesses sensitive environment variable configured in the server environment

9. $GLOBALS : Allowws access to user-defined global variables from any scope inside your script.

-> Key Examples and Best practices:
$_SERVER keys demonstrated:

1. $_SERVER["Document_root"] : Returs the root directory path of the website on the machine (e.g, c:/xampp/htdocs)

2. $_SERVER["PHP_SELF"] : Retures the folder and filename of the currently executing script

3. $_SERVER["SERVER_NAME"] : Returns the name of the host server 

4. $_SERVER["REQUEST_MEATHOD"] : Returns the request meathod used to access the page

5. Use $_GET when retriveing or displaying non-sensitive data (e.g, loading a user's profile page or passing query parameters like ?name=Danny&eyecolor=Blue)

6. Use $_GET when submitting sensitive data or modifying data in a database (e.g, login credentials), as it keeps values hidden from the URL

Avoid $_REQUEST for general for handling:

Because $_REQUEST pulls from multiple sources (GET, POST adn COOKIE) simultaneously, you loose certainty over wheere the data originated, which introduces security risks if not strictly validatedd. Stick explicitly to $_GET or $_POST 

validating uploads with $_FILES:

ALways inspect uploading file attributes (such as file size and extension) via $_Files before saving them to you server to prevent malicious or oversized uploads from crashing your site
